# 📊 H100 GPU 랙 기반 LLM 추론 인프라 정합성 검증 보고서

본 보고서는 **NVIDIA DGX H100 계산 랙 1개(32 GPU)** 환경에서 거대 모델(**Qwen 235B급**)을 서빙할 때, 제안서 차트 데이터(**소모전력 0.040 MW, 총성능 6,000 TPS**)가 하드웨어 물리 법칙과 데이터센터 인프라 관점에서 성립할 수 있는 최적의 조건을 도출하고 검증한 최종 요약 문서입니다.

---

### 1. 초기 가설의 한계 및 비판적 검증 (Dense BF16의 모순)

초기 시나리오인 **"Dense 아키텍처 및 오리지널 BF16 정밀도"** 환경에서는 차트값과 실제 실측 성능 간에 **약 1.8배의 심각한 성능 격차**가 발생하며, 시스템이 물리적으로 성립하지 않습니다.

* **통신 병목 (All-Reduce Overhead):** Dense 235B 모델은 GPU 1장에 탑재가 불가능하여 32장 전체에 분산(Tensor Parallelism 등)해야 합니다. 매 토큰 생성 시 노드 간 인피니밴드 통신 오버헤드로 인해 실효 대역폭 효율(MBU)은 45% 이하로 추락합니다.
* **메모리 한계 (Memory Wall):** 32K 컨텍스트 환경에서 32장 GPU의 이론상 절대 상한선은 **7,396 TPS**입니다. 차트값(6,000 TPS)은 하드웨어 성능을 81% 이상 짜내야 하므로 소프트웨어 및 통신 마진(19%)이 턱없이 부족합니다.
* **VRAM 및 전력 한계:** 유저 120명의 32K KV 캐시가 남은 VRAM의 81%를 차지하므로, 첫 질문을 읽는 Prefill 단계의 활성화 메모리가 겹치는 순간 **100% 확률로 OOM(Out of Memory) 에러**가 발생합니다. 또한 공랭식 랙은 40 kW 풀가동 시 쓰로틀링이 발생합니다.

---

### 2. 차트 부합을 위한 마스터 아키텍처 제안 (성립 조건)

제안서 차트의 **6,000 TPS / 0.040 MW**가 단순 마케팅 수치가 아닌 **실제 구동 가능한 실측치**가 되기 위해서는 다음과 같은 하드웨어·소프트웨어 조건의 완전한 전환이 필요합니다.

1. **모델의 MoE 변환:** 전체 파라미터는 235B이지만, 토큰당 일부 전문가만 활성화되어 실제 연산량을 **60B 수준으로 낮춘 MoE 구조**를 채택해야 합니다.
2. **FP8 양자화 적용:** 가중치 정밀도를 BF16에서 **FP8**로 압축하여 HBM 대역폭 압박을 절반으로 낮추고 VRAM 안전 마진을 강제로 확보합니다.
3. **액체 냉각(DLC) 도입:** 랙당 40.8 kW의 고밀도 열을 식히고 데이터센터 **PUE를 1.1 이하로 통제**하기 위해 직분사 액체 냉각 인프라를 전제합니다.
4. **Continuous Batching 최적화:** 인당 50 TPS의 개별 스트리밍이 아닌, 고부하 API 환경에서 **대규모 배치(Batch Size 512 이상)로 묶어 처리**함으로써 가중치 재사용률을 극한으로 끌어올립니다.

### 4. 핵심 엔지니어링 결론

"본 인프라 제안서의 **랙당 0.040 MW 전력 대비 6,000 TPS** 공급 능력은 하드웨어 물리 제약상 순수 Dense 모델로는 달성이 불가능합니다. 그러나 최신 vLLM/SGLang 엔진을 기반으로 **FP8 양자화가 완료된 Qwen 235B MoE 모델**을 탑재하고, **직분사 액체 냉각(DLC)** 환경에서 대규모 배치 스케줄링을 통해 구동하는 환경임을 정의한다면, 본 차트의 수치는 완벽하게 구현 가능한 **'물리적 실측 팩트'**로 성립합니다."
