1. 요약 & 핵심 쟁점 (Executive Summary)

CXL은 2019년 PCIe PHY 위에 캐시 일관성을 올린 개방형 인터커넥트로 출발해, 2025-2026년 AI 랙의 메모리 계층 재설계라는 전환점에 진입했습니다. 핵심 쟁점 3가지:

쟁점 1
AI 패브릭 진영 대치
NVIDIA NVLink(NVL72) vs UALink 컨소시엄. CXL은 GPU 스케일업이 아닌 메모리 분해 영역에서 보완
쟁점 2
Memory Wall & TCO
LLM 추론 KV cache가 주요 제약 (70B@128k≈40GB, 405B≈66GB). HBM 부족/고가 → CXL 풀로 CAPEX 절감
쟁점 3
컨트롤러 벤더 생태 분화
Panmnesia/XCENA/ScaleFlux/Marvell/Montage/Astera/Microchip이 각기 다른 use case로 시장 공략
핵심 인사이트: 컨트롤러 벤더 솔루션 맵핑이 신제품 컨셉 기획의 핵심 입력입니다. 특히 XCENA(액시나)의 RISC-V 기반 컴퓨테이셔널 메모리 컨트롤러(MX1, CXL 3.2, KV cache 오프로드)는 신제품 컨셉에 핵심 반영 대상입니다.

4.7 풀링 심층 (아키텍처 모드·티어링·use case·TCO)

4.7.1 세 가지 메모리 모델 구분 상품기획 핵심

모델CXL 버전토폴로지특성
Expansion(확장)1.1+단일 호스트 직접 연결용량 증설, 단순. seamless capacity upgrade
Pooling(풀링)2.0PCIe 스위치 패브릭, 다중 호스트독립 노드가 공유 풀에서 격리된 할당. stranded memory 제거
Sharing(공유)3.0멀티홉 패브릭다중 호스트가 동일 데이터 동시 읽기, 복제 없는 진정한 공유
핵심: CXL 2.0 = pooling(격리 할당), CXL 3.0 = sharing(동시 공유)로 진화. 이 차이가 상품기획 포지셔닝의 핵심.

4.7.5 레이턴시/성능 트레이드오프 (중요)

remote CXL 액세스 = 로컬 대비 레이턴시 2.2x~4x 증가, 처리량 감소. "remote DRAM과 비슷하나 bandwidth는 낮음". CXL 4.0(128 GT/s)이 개선하나 오버헤드 잔존. → latency-sensitive 워크로드는 local DDR5 우위. 풀링은 용량/탄력 이점이 필요한 워크로드에 적합.

OLTP✗ 회피레이턴시 민감, local DDR5 우위 → 초기 도입 회피 권고
"AI inference KV cache offload, Redis, Spark shuffle이 가장 깨끗한 파일럿 승리처". OLTP는 회피. use case 선택이 상품기획 성패 좌우.

7. Main Memory ↔ CXL 미디어 연관성

7.1 메인메모리 DRAM 동향

  • DDR6: 목표 최대 17.6 Gbps. 프리미엄 2026년 상용화, 2027년 대량 채택 예상
  • LPDDR6: JEDEC 2025.07 최종 스펙 확정. CAMM2 호환, LPCAMM2/SOCAMM2 도입, 512GB 전망, PIM 변종 개발 중
  • Micron MRDIMM/MCRDIMM: DDR5-8800, 최대 256GB. 128GB DDR5-8800 MRDIMM이 DDR5-6400 RDIMM 대비 로디드 레이턴시 40% 감소. 듀얼소켓 Granite Rapids + MCRDIMM: 피크 메모리 처리량 1.5 TB/s

7.2 3계층 분담

계층위치특성역할

주의: CXL은 로컬 DDR5 대비 레이턴시 높음 → "latency-sensitive 워크로드는 여전히 local DDR5 우위". 용량/풀링 이점이 필요한 워크로드에 적합.

8. AI Rack 메모리 계층 & KV offload 응용

8.1 계층

GPU HBM(온패키지, 최고 대역/최소 용량) → CPU DRAM(호스트) → CXL 메모리 풀(용량/탄력/공유) → NVMe SSD(청크 로딩, KV cache 스필). weights → HBM, activations → HBM, KV cache → CPU/CXL/SSD 계층화.

8.2 KV cache offloading

  • vLLM/PagedAttention: KV cache를 CPU/CXL/SSD로 오프로드
  • Mooncake (Kimi): prefill/decode 분리(disaggregated), 중앙 집중 KV 캐시 저장소. Kimi K2 대규모 배포. vLLM/SGLang 호환
  • LMCache / NVFP4 양자화 / CPU offloading으로 VRAM 압박 완화
  • CXL shared memory pools로 인프라 비용 절감 + 확장 효율

8.3 관련 논문

  • Mooncake: prefill/decode 분리, 그렇지 않으면 유휴인 CPU/RAM/SSD/NIC을 중앙 집중 KV 캐시 저장소로 통합. "HBM alone cannot hold full weights + KV cache" → CXL 풀링으로 용량 확장
  • DeepSeek V3, DistServe, Splitwise: prefill/decode 분리 서빙 아키텍처 — GPU 자원 활용률 극대화

12.2 제품 포지셔닝 옵션

  1. 풀 스택(Appliance+SW): 삼성식 — 컨트롤러+모듈+스위치+오케스트레이션 콘솔
  2. 컨트롤러/IP 전문: Panmnesia/Montage식 — 벤더에 IP 공급
  3. AI 랙 특화: KV cache 오프로드 CXL 풀 + GPU 호스트 통합
  4. 진영 중립적 메모리 풀: NVLink/UALink 모두에 부착 가능
  5. 풀링 단계별 포지셔닝: Expansion(1.1) → Pooling(2.0) → Sharing(3.0) 3단계 라인업. 각 단계별 타겟 워크로드 분리

12.3 핵심 기회 영역 & 차별화 use case

  • AI 추론 KV cache 풀: Mooncake/vLLM disagg 서빙 결합 — 가장 큰 단기 기회, cleanest pilot win. Penguin MemoryAI(11TB)/MemVerge+XConn(100TiB, SSD 대비 5배+) 검증
  • Redis / Spark shuffle: 풀링 cleanest win — 피크 용량 흡수, overprovisioning 절감
  • 장문 컨텍스트(128k~1M) 지원: CXL 풀로 HBM 한정 우회
  • DB/인메모리 분석: 마이크론 CZ120 실적(쿼리 96%↑) 검증
  • CSP composable infra: stranded DRAM → shared pool
  • (회피) OLTP: 레이턴시 민감, local DDR5 우위 → 초기 풀링 타겟 아님
