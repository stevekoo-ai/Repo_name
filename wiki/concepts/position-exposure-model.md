# Position & Exposure Model

보고서 **0절**의 설계 근거. 구현: `engine/exposure/model.py`.

---

## 왜 만들었나 — 한 달간의 구조적 오진

2026-07~08 한 달 동안 이 저장소는 **거시경제 관측소**로 성장했다.
거시 엔진, 위기지수, 금리 분석, 12주 추세, 롤링 집계, 경제 캘린더가 차례로 붙었고
전부 정상 작동한다. 그런데 사용자가 실제로 답을 원한 질문은 두 개뿐이었다.

1. SK하이닉스를 계속 들고 갈 것인가
2. 집을 언제 살 것인가

**두 질문 모두 거시 질문이 아니다.** 익스포저 질문이다.
그리고 둘은 별개가 아니라 **하나의 문제**다 — 집 살 현금이 주식 안에 잠겨 있기 때문이다.

2026-08-10 이전까지 `sk_hynix_decision.py`와 `real_estate_decision.py`는
나란히 실행되며 **값을 하나도 주고받지 않았다.** 그래서 모든 섹션이 "정상"이어도
두 질문 중 어느 쪽에도 답이 나오지 않았다. 이것이 "다 읽었는데 가져갈 게 없다"의 정체다.

## 설계 원칙 (훼손 금지)

### 1. 수집기와 완전히 분리된다

`config/portfolio.yaml`만 읽는다. 네트워크를 쓰지 않는다.

이건 편의가 아니라 **설계 목적**이다. 2026-08-10 실행에서 한국 10개 지표 중
7개가 이월, 미국은 8개 전부 이월이었다. 그날 보고서에서 유효한 정보를 담고 있던
섹션은 0절뿐이었다. **가장 자주 맞는 섹션이 가장 앞에 와야 한다.**

### 2. 시세를 지어내지 않는다

`KNOWN_PRICES`에 관측일·출처와 함께 등록된 종목만 시가 평가한다.
없는 종목은 **매수원가**로 계산하고 "원가 기준"이라고 명시한다.
평가액 중 검증된 시세가 차지하는 비율(`priced_coverage_pct`)을 함께 출력한다.

> ❌ 금지: 시세가 없다고 `avg_price`를 조용히 시가로 쓰는 것.
> 그러면 손익이 항상 0으로 나오면서 정확해 보인다 — 최악의 실패 방식이다.

### 3. 브로커 잔고가 아니라 사이클 노출을 센다

세 겹을 함께 본다.

| 층 | 내용 | 반영 |
|---|---|---|
| 종목 | SK하이닉스 248주 | `employer_pct` |
| 섹터 | 삼성전자·제주반도체·반도체 ETF까지 | `semi_pct` |
| 소득 | 급여·성과급(PS)·퇴직연금 | 정성 경고(`notes`) |

`SEMI_SECTORS` / `SEMI_ETF_BUCKETS`가 섹터 판정 기준이다.

### 4. 락업을 결정 변수에서 제외한다

67주는 2027-02-11까지 매도 불가(만기 전 매도 시 마크업 8,791,650원 소멸).
따라서 **"몇 주를 조정할까"의 정답 공간은 248주가 아니라 181주**다.
`sellable_qty`가 이 값이다.

### 5. 두 결정을 잇는다 — `deployable_cash`

```
deployable_cash = 현금 + (총평가액 − 락업평가액)
```

**부동산 진입 여력을 결정하는 것은 기준금리가 아니라 이 숫자다.**
3절(부동산)의 WAIT/ENTER는 이 값과 함께 읽어야 의미를 갖는다.
이 필드가 두 엔진을 연결하는 다리다. 2026-08-10에 `real_estate_decision.py`의
`_compute_affordability()`가 이 값을 실제로 읽도록 결선 완료(3절 "자금 현실").

## 2026-08-10 최초 산출 결과

기존 20여 개 섹션 어디에도 없던 숫자들이다.

| 항목 | 값 |
|---|---|
| 주식+ETF 평가액 | 4.02억원 |
| **반도체 섹터 비중** | **96.1%** |
| SK하이닉스 단독 | 3.56억원 (88.6%) |
| 평단 대비 | 3.01배 (+200.8%) |
| 락업 | 67주 (2027-02-11) |
| 즉시 조정 가능 | **181주** |
| **주택 진입 가용 현금** | **3.26억원** |
| 시세 검증 커버리지 | 89% (나머지 원가 기준) |

**해석**: 위험은 "SK하이닉스 한 종목"이 아니라 **포트폴리오의 96%가 하나의
메모리 사이클**이라는 것이다. 여기에 급여·PS·퇴직연금이 같은 회사에 연동되므로
실질 집중도는 96.1%보다 높다. 이 사실은 CPI 발표나 기준금리 결정과 무관하게
**오늘 이미 참이며, 데이터가 없는 날에도 판단 가능한 유일한 항목**이다.

## 확장 방향 (우선순위 순)

1. **시세 연동** — `KNOWN_PRICES`를 KIS API 실시간 조회로 대체.
   ([kis-api-reference.md](kis-api-reference.md)) 이것만으로 0절이 살아 움직인다.
2. **집중도 상한선** — 사용자가 정한 반도체 비중 상한을 `portfolio.yaml`에 넣고,
   초과 시 0절이 자동 경고. 이벤트 당일 감정이 아니라 규칙으로 대응하게 하는 장치.
3. ~~**부동산 엔진과 실제 결선**~~ ✅ **완료 (2026-08-10)** —
   `real_estate_decision.py`에 `_compute_affordability()` 신설, `deployable_cash`를
   서울 평당가와 결합해 3절에 "자금 현실" 블록으로 출력.
   **임계값은 일부러 만들지 않았다** — 목표 지역·평형을 모르는 상태에서 "N억 필요"를
   하드코딩하면 추측이 규칙처럼 보이기 때문. 대신 자금이 실제로 어디까지 닿는지
   (매매 7.4평 / 전세 12.6평)와, 숫자에서 바로 따라 나오는 결론 하나만 적는다:
   **주택 자금 마련 = 반도체 집중도 완화** (같은 매각 행위).
   남은 확장: 대출 한도 반영, 목표 지역·평형 입력받기.
4. **소득 상관 정량화** — PS를 회사 실적 함수로 모델링해 실질 집중도를 숫자로.
