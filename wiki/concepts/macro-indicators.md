**한국 반도체 산업 전체의 실물 수요(메모리+비메모리 합산 통관 기준)를
정부 통계로 매달 재확인하는 유일한 축**이라, 개별 종목·개별 고객사
데이터에 없는 "산업 전체가 여전히 뜨거운가"라는 독립 신호를 제공한다.
[HBM Cycle Score "가설이 깨지는 조건" ⑤](hbm-cycle-score.md)로 채택됨.

**경고 조건 (사용자 지정)**: YoY 증가율이 **10% 미만으로 하락**하면

### 🔴 PEOS의 "반도체 수출 증가율 24.7%"는 가짜 예시값 (2026-08-05 저녁, 사용자 질의로 발견)

**사용자 질의**: "PEOS는 왜 반도체 수출 증가율이 24% 수준이지?" —
`report/2026-08-05.md`의 Macro Dashboard가 위 기준선(+178.8%)과 완전히
다른 **24.70%**를 보여주는 걸 사용자가 발견.

**원인 (소스 확인)**: PEOS(별도 `main` 브랜치 자동화 시스템)의 반도체
수출 지표는 `data/manual_inputs/exports.yaml`이라는 **사람이 손으로
매달 채워 넣어야 하는 수동입력 파일**에서 온다(`collectors/manual.py`
— 산업통상자원부 수출입 동향은 안정적 공개 API가 없어 수동입력으로
설계됨). 그런데 이 파일은 **"EXAMPLE" 딱지가 붙은 자리채움용 더미
값**(4월 18.9%→5월 22.4%→6월 24.7%, 완만한 우상향 예시 패턴) 그대로다
— `git log`로 확인한 결과 **PEOS를 만든 최초 커밋(`e4dcd23`) 이후 단
한 번도 실제 값으로 교체된 적이 없다**. 오늘 리포트의 "현재=이전
=24.70, 총수출도 현재=이전=9.10"이라는 패턴 자체가 매달 갱신되고
있었다면 나올 수 없는 모습이라 이게 결정적 증거.

**파급 범위**: 이 가짜 값이 `engine/macro/regime.py`(한국 거시국면
판정의 semiconductor_strong/semiconductor_export_slump 신호)와
`engine/semiconductor/score.py`(반도체 서브스코어) 산정에 그대로
쓰이고 있어 — **PEOS의 한국 경기판단·반도체 스코어가 이 기간 내내
가짜 데이터를 입력값으로 산출돼왔다**는 뜻. 총수출(9.10%)도 동일한
문제.

**이 위키와의 관계**: 이 페이지 위쪽 "반도체 수출 증가율 추적"
섹션(+178.8%)은 이번에 웹검색으로 직접 검증한 **실제 수치**이고
PEOS와는 완전히 독립적인 별도 파이프라인 — 서로 다른 시스템이라
자동으로 동기화되지 않는다는 게 이번에 실증됨. PEOS 쪽 수정
(`data/manual_inputs/exports.yaml`을 실제 값으로 갱신)은 `main`
브랜치가 자동화 운영 기준이라 사람 손 커밋을 지양하는 이 저장소의
브랜치 원칙([CLAUDE.md](../../CLAUDE.md))에 따라 **사용자 확인 후
진행 여부 결정** — 이번 세션에서는 발견·보고만 하고 수정은 보류.

### 데이터 수집 자동화 경로 검토 (2026-08-05, 사용자 질의)

**사용자 질의**: "API를 통해 수집할 수 있는 데이터인지 확인해줘, 메모리
수출 YoY + D램 수출 YoY + NAND 수출 YoY로 세분화될 수 있는지도 검토해줘.
DATA_GO_KR_KEY에서 가능하다는데?!" + 제안 파이프라인(DATA_GO_KR_KEY→반도체
수출 자동화, KOSIS_API_KEY→백업, ECOS_API_KEY→경상수지/금리/GDP,
FRED_API_KEY→미국 경기판단).

**결론 요약**: API 수집 가능성 — **가능성 높음, 단 라이브 검증 미완료**.
메모리/D램/낸드 세분화 — **가능 (강한 정황 증거로 확인)**. 제안 파이프라인
스코핑 — **방향은 맞으나 핵심 전제 1개는 미확인**.

**1) 메모리/D램/낸드 세분화가 실제로 존재하는가 — YES, 확인됨**
산업통상자원부가 **2026년 1분기 수출입동향부터 MTI 코드 체계를 6년 만에
전면 개편**해, 기존에 "반도체" 하나로 뭉뚱그리던 통계를 **메모리반도체
(D램/낸드 별도 세분화)·시스템반도체**로 나눠 월간 보도자료에 정식 발표하기
시작했다(경향신문 2026-05-06 "반도체 초호황에 1분기 수출 역대 최대···
수출입 통계 기준 6년 만에 개편" 등 복수 매체 확인). 실제 발표 수치 예시
(2026년 1분기, 복수 매체 교차확인): D램 +249.1% YoY($357.87억), 낸드
+377.5% YoY($53.86억), 시스템반도체 +13.5% YoY($121.08억), 메모리반도체
합산(1월 기준) +154.4% YoY($157.2억). **즉 사용자가 원하는 3개 지표
(메모리/D램/낸드 YoY)가 이미 정부 공식 통계로 매달 존재한다** — 새로
만들 필요 없이 기존 발표를 받아오면 됨.

**2) API로 수집 가능한가 — 후보 2개 확인, 라이브 테스트는 미완료**
- **후보 A: `data.go.kr/data/15051126`("산업통상자원부_반도체디스플레이
  수출동향 추이")** — 검색 결과 상 D램·낸드·MCP·시스템반도체·이산소자
  수출액(억달러)+YoY를 2015-01부터 월별로 제공한다고 명시됨(가장 직접적인
  후보). 다만 카탈로그 URL이 `openapi.do`가 아니라 `fileData.do`로
  분류돼 있어 — data.go.kr은 3성급 이상 파일데이터를 자동으로 OpenAPI로도
  변환해 제공하는 기능이 있다고 알려져 있으나, 이 데이터셋이 실제로 그
  변환 대상인지, 정확한 REST 엔드포인트가 무엇인지는 **확인하지 못함**
  (아래 "검증 못한 이유" 참고).
- **후보 B: `data.go.kr/data/15101609`("관세청_품목별 수출입실적(GW)")**
  — 이건 확실히 `openapi.do`(라이브 REST API), HS코드 2/4/6/10자리
  기준 집계. HS 854232가 "메모리"(Memories) 세번인 것은 국제 HS 표준으로
  확인됨. 다만 **D램 vs 낸드를 나누는 정확한 한국 10자리(HSK) 세분류
  코드는 신뢰할 만한 출처로 확인하지 못함** — 한 블로그가 "8542.32.1010=
  삼성전자 D램, 8542.32.3000=SK하이닉스 MCP(HBM)"라고 주장하지만, **HS
  코드는 원래 회사별로 분류되지 않으므로 이 주장은 사실이 아닐 가능성이
  매우 높음 — 채택하지 않음, 반드시 관세법령정보포털(CLIP,
  unipass.customs.go.kr)에서 직접 재확인 필요**.
- 참고로 **`tradedata.go.kr`(관세청 수출입무역통계 공식 포털)**,
  **`bigdata.customs.go.kr`(관세청 빅데이터 포털)** 도 발견됨 — data.go.kr
  경유가 막힐 경우의 대안 경로로 추가 조사 가치 있음(미착수).

**검증 못한 이유 (투명하게 기록)**: 이번 조사에서 data.go.kr 상세페이지
(`www.data.go.kr/data/*.do`)와 관련 블로그 글 모두 WebFetch 시 **HTTP 403**
(봇 차단으로 추정, [`collectors/molit.py`](../../collectors/molit.py)
헤더 주석에 이미 기록된 것과 동일 패턴). 또한 이 세션의 아웃바운드 프록시가
`apis.data.go.kr:443`으로의 CONNECT 자체를 **정책적으로 차단**함(`curl`로
직접 확인 — "gateway answered 403 to CONNECT"). 즉 이 세션 자체에서는
data.go.kr 계열 API를 라이브로 호출할 수 없다 — **실제 검증은 GitHub
Actions 러너(진짜 네트워크 접근 + `DATA_GO_KR_KEY` 시크릿 보유)에서
`workflow_dispatch` 진단 프로브로 해야 함**, 이 저장소에 이미 같은 목적의
선례가 있음(`.github/workflows/ecos-lookup.yml`, `kosis-lookup.yml`,
`subscription-schema-probe.yml`).

**3) `DATA_GO_KR_KEY` 활용신청 주의사항**: [자동화
인프라](../entities/automation-infrastructure.md)에 이미 기록된 대로,
data.go.kr은 **같은 키라도 API 상품 단위로 별도 승인**이 필요하다 — 현재
이 저장소가 승인받아 쓰고 있는 상품은 "아파트매매 실거래 상세자료"·
"청약(Applyhome)" 2개뿐, 위 후보 A/B가 승인돼 있는지는 **미확인** — 승인
안 됐다면 신청부터 필요(관세청 상품은 보통 즉시~1일 자동승인인 경우가
많다고 알려져 있으나 확인 필요).

| `KOSIS_API_KEY` → 백업 데이터 소스 | 포지셔닝은 합리적(KOSIS가 관세청 원자료를 재게시하는 사례가 있음)이나, 이번 조사에서 D램/낸드 세분류를 가진 구체적 KOSIS `tblId`를 찾지 못함 — 지금 당장 신뢰할 백업으로 보기엔 이름 확인이 더 필요 |
| `ECOS_API_KEY` → 경상수지/금리/GDP | 정확함 — 이미 [`collectors/ecos.py`](../../collectors/ecos.py)가 이 용도로 사용 중, 품목별 반도체 세분류는 ECOS 소관 아님 |
| `FRED_API_KEY` → 미국 경기판단 | 정확함 — 이미 이 용도로 사용 중, 한국 반도체 수출과 무관 |

**다음 단계 제안**: `ecos-lookup.yml` 패턴을 그대로 따르는 신규
`workflow_dispatch` 진단 프로브(예: `semiconductor-export-api-probe.yml`)를
만들어 후보 A/B 엔드포인트를 실제 `DATA_GO_KR_KEY`로 호출해보고, 응답
스키마(D램/낸드 필드 존재 여부)와 활용신청 상태를 확정한 뒤에 실제
수집 스크립트(`collectors/*.py`)를 작성하는 것이 CLAUDE.md의 cross-check
원칙에 맞음 — 검증 전 코드 작성 금지. 사용자 승인 대기 중(2026-08-05).
