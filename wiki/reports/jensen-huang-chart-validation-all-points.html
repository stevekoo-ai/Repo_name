H100 @ x=50 검증 methodology를 모든 12 포인트에 적용. 각 포인트가 해당 bottleneck state에서 그 값에 수렴될 수밖에 없음을 증명.

📋 검증 methodology (H100 @ x=50에서 확립)

각 포인트에 대해 5단계 계산:
1. batch_size = TFLOPS_total / (x × 470B) — compute-based theoretical max
2. Concurrent users = chart TPS/MW × rack_MW / x
3. KV BW 사용률 = KV_cache × TPS / HBM_total_BW → bottleneck classification
4. iteration_latency = compute + KV_memory(400x L2 miss) + prefill + TP_sync + scheduling
5. computed TPS/MW = batch_decode / iteration_latency / rack_MW → chart 값과 비교

고정 가정 (235B dense, 32K context, Qwen 3 class):

LLM:           235B params, 88 layers, GQA (128→8 KV heads), FP8 decode
FLOPs/token:   470B (2 × 235B)
KV/cache:      0.453 MB/token, 14.1 GB/user (32K context)

Overhead model (arxiv 2503.08311 + 40M DAU production 검증):
  L2 miss penalty: 400x (L2 hit rate 0.83-1.60% → 98%+ HBM 직접 읽기)
  TP sync:         0.215 msec (NVSwitch all-reduce × 88 layers)
  Scheduling:      0.15 msec (vLLM scheduler + kernel launch)
  Prefill ratio:   concurrency에 따라 20-90% (동일 LLM, 동일 batch에서 더 높은 concurrency일수록 prefill占比 ↓)
