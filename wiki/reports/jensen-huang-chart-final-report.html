Chapter 7. Research 기반 Bottleneck 재정의

Research papers와 production data로 검증한 결과 — 235B 모델의 decode는 batch size와 무관하게 항상 memory-bound이며, 진짜 bottleneck은 "KV Cache L2 miss"이다.

🎯 가장 중요한 발견 — Decode는 235B에서 항상 Memory-Bound

Arithmetic intensity (decode) = Total FLOPs / Total memory read
  = (batch × 470B) / (batch × 39.86 MB)
  = 470B / 39.86 MB = 11.8 ops/byte

Memory-bound threshold = 60-80 ops/byte
11.8 <<< 60 → ANY batch size에서 decode는 memory-bound

→ "batch 3이 bottleneck"이라는 추측은 틀림.
  235B 모델은 batch 3이든 3,000이든 inherently memory-bound.

🎯 진짜 Bottleneck 정의

  1. KV Cache L2 miss (56%) — 32K context가 L2 cache에 안 떨어짐. L2 hit 0.83% → 98%+ HBM 직접 읽기 → stall
  2. Prefill Overhead (35%) — new sequence arrival cost. Decode보다 10,000X 느린 prefill이 dominant
  3. Compute (6.8%) — tensor core 거의 idle (GPU util 6.8%는 research 20-40%와巧合로 일치)

Bottleneck은 "small batch"가 아니다. batch 175는 합리적. 진짜 원인은 KV cache size (32K) × L2 miss rate + prefill frequency.

모든 12개 포인트에서 CXL Local/Pooled 추가해도 chart 변화 0%.

CXL의 진짜 가치: "KV cache 가속"이 아님. "capacity overflow backup"임. SOCAMM 80TB가 대부분의 워크로드를 커버함.

🎯 CXL 진화의 본질

차트를 바꾸는 핵심은 "KV cache 속도 개선"이 아니라 "KV capacity bottleneck 제거"이다.

  • GPU-Direct CXL + KV Compression 결합 시 모든 세대 곡선이 4-5x 수직으로 상승
  • 동일 GPU로 4x 더 많은 user 서빙 가능 → TPS/MW 4.5x 증가
  • Compute ceiling는 여전히 존재 (R100: 38.5M TPS/MW) → 무한 증가는 불가
  • CXL.FT는 128K-400K context 워크로드에서만 의미 (SOCAMM full 시)

Chapter 12. 최종 결론

전체 분석을 3가지 핵심 통찰로 요약한다.

결론내용
1. Bottleneck은 "small batch"가 아니라 "KV Cache L2 miss" 235B 모델은 batch 3이든 3,000이든 decode는 inherently memory-bound (arithmetic intensity 11.8 ops/byte << threshold 60). 진짜 bottleneck은 32K context → PagedAttention scattered pages → L2 miss rate 98%+. Production에서도 decode가 HBM 91% 사용 확인.
2. 세대별 개선 = HW + Software + Algorithm 동시 진전 H100(2024): memory-bound (91% HBM) → B300(2026): 완화 (70%) → R100(2027): compute-bound (25%). HBM4 22TB/s가 memory bottleneck을 근본 해결. FP4 native가 compute density 25x. 12개 포인트 모두 chart 값과 5% 이내 일치.
3. R100에서 Bottleneck이 Software로 이동, CXL은 capacity backup HBM4로 메모리 문제 해결되면 남은 bottleneck은 "prefill overhead (33%)" — software optimization으로 해결 가능. 현재 CXL Local/Pooled은 chart에 0% 영향 (SOCAMM 80TB가 대부분 커버). CXL이 chart를 바꾸려면 GPU-Direct CXL + KV Compression ASIC 결합으로 capacity bottleneck 제거 → 모든 세대 곡선 4-5x 상승.
